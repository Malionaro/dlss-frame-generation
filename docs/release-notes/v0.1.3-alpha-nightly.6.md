## Vulkan Frame Generation nightly 6 (after 0.1.2-alpha)

Untested debug nightly for **Minecraft 26.3** (Fabric, Vulkan backend). It is meant to find out why the RT engine draws nothing; back up your worlds. The JAR still carries the version `0.1.2-alpha` in its name.

### What changed

- **Automatic fallback for the RT pass.** Nightly 5 showed that the RT shader never started a single workgroup while it was recorded into Minecraft's current command buffer. After 90 frames the mod now checks this; if the shader never ran, it records the RT pass into its own command buffer that Minecraft executes in order (the way other RT mods submit their work) and logs the switch. `rayTracingOwnCommandBuffer: true` in the config forces this path from the start.
- **More RT debug output in `latest.log`:**
  - `RT debug:` whenever the traced size, output image, scene or instance count changes (dispatch size, image and pipeline handles, sections, entity and particle geometry, command buffer).
  - `RT shader:` every 5 s: started workgroups vs. expected, the output size the shader sees, whether a Minecraft render pass was open.
  - `RT self-check` / `switching the RT pass to its own command buffer` after 90 frames.
  - `RT pass not called in the last 5 s:` with the reasons, if the pass was skipped.

### Please send

Turn RT on, walk around for about 30 seconds and send `latest.log` (all lines starting with `RT`).

### Install

Replace the old JAR in `mods` (Fabric Loader 0.19.5+, Fabric API, Vulkan backend).
